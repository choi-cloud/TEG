## 6. 이상 징후
1. 게이트 G1·G2 실패(3절). 원본 코드 1-shot 반복 실행에서도 정확도가 달라진다(진단 1). T01·T02의 결정성 확인은 Amazon_clothing 5w1s seed 0만 대상이었다.
2. off 정확도가 같은 실행 사이에서도 `auc_phat_pooled`가 최대 0.0035 다르다(진단 2, T05 코드 이전 실행 포함).
3. 각 run 안에서 `auc_phat_pooled_raw`는 기존 `auc_phat_pooled`와 전 에폭 같다(30/30).
4. dblp 1-shot의 `−d_final` AUC가 seed마다 크게 다르다: seed 0–4 = 0.9169, 0.9270, 0.8269, 0.8265, 0.6718 (`−d0`: 0.8858, 0.9024, 0.8984, 0.8879, 0.8715).
5. 표 C의 `−d0` AUC는 모든 셀에서 0.0000이다. 부분집합을 d0 백분위로 정의해, same=1은 d0 ≥ 75백분위이고 same=0은 d0 ≤ 25백분위이기 때문이다.
6. 표 C의 부분집합은 same=0이 대부분이다(예: Amazon_clothing 1-shot 27.2 vs 1252.0).
7. 표 D: `top1_raw` 평균 0.99999 이상, `top1 − top10` 차 1e-5 이하. `center`는 0.9997 이상. `str`은 0.966–0.993.
8. 자율 판단 내역:
   - `top10_<key>`는 k(=`mem_k` 10)번째 유사도로 저장했다.
   - `dir`은 간선 배열 앞 절반을 0(query←support), 뒤 절반을 1로 저장했다(task 그래프 간선 생성 순서).
   - `auc_phat_pooled_<key>`·`auc_dfinal_pooled`는 `--dump_edges`와 무관하게 `--mem`이면 기록한다.
   - G1 5-shot 판정은 T03b 정의대로 valid/test 22개 값만 사용했다(train 최대 차도 표 E에 기록).
   - 표 B는 `GroupKFold(5)`(셔플 없음), `StandardScaler` + `LogisticRegression()` 기본값을 썼다.
   - 표 B·C·D의 sd 표기 형식(부호 제거)을 한 번 고쳐 다시 생성했다. 값은 그대로다.
9. 진단용 worktree(`scratchpad/wt_t01`)는 `git worktree remove --force`로 제거했다(dataset 링크 때문에 `--force` 필요). 원본 dataset 파일 크기는 변화 없음.
