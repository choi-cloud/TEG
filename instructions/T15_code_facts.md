## 3. 보고할 사실

모든 항목에 `파일:줄`을 붙인다. 코드 인용은 필요한 줄만 짧게 한다.

### A. 손실 항 전체

- 학습 1 step의 총손실을 구성하는 모든 항을 다음 표로 정리한다. TEG 원본 항, 손실에 더해지는 정칙화, 보조 손실(`kl_h2`, `infonce`, BSC 경로)을 모두 포함한다.

  | 항 | 코드 위치 | 수식(코드 그대로) | 입력 텐서(어느 모듈의 출력인가) | 참여 노드(support / query / anchor / 그 외) | 사용 레이블 | 기본 가중치 |
  |---|---|---|---|---|---|---|

- γ의 인자 이름, 기본값, 실제로 곱해지는 위치.
- L_N과 L_G 각각이 EGNN 출력을 쓰는지, GCN 출력을 쓰는지, 둘 다인지.

### B. GCN 파라미터로 가는 gradient 경로

- 인코더(GCN) 파라미터 목록(이름, 모양).
- GCN forward 정보:
  - 전체 그래프에 대한 forward인지, 부분 그래프인지
  - 학습 1 step에서 몇 번 호출되는지
- 각 손실 항에서 GCN 파라미터까지의 계산 경로를 모듈 순서로 적는다. 예: GCN → LayerNorm → EGNN 좌표 입력 → … → L_N.
- `detach()`, `torch.no_grad`, `requires_grad=False` 등 gradient를 막는 모든 연산의 위치와 대상.
- 판정 표:

  | 항 | GCN에 gradient 도달(정적 판단) | 근거 줄 | 동적 확인 필요 여부 |
  |---|---|---|---|

### C. anchor와 노드 참여

- anchor 16개에 대해:
  - 정체(무엇인가)
  - 선택 방법(무작위라면 전역 `random`인지)
  - 출처 노드 집합(base 클래스 노드만인지, 전체 노드인지)
  - 손실에서의 역할
- 학습 step에서 임베딩이 손실에 직접 들어가는 노드가 어떤 클래스 그룹에 속할 수 있는지(base만 / valid·test 노드도 가능).

### D. 최적화와 정칙화

- optimizer 종류. param group별 파라미터, lr, weight decay.
- dropout의 위치와 비율, LayerNorm 위치, 그 밖의 정규화, gradient clipping, scheduler.
- 1 에폭이 몇 step인지. `optimizer.step`과 `zero_grad`의 위치.
- train/eval 모드 전환 위치.

### E. 레이블 사용 지점

- base, valid, test 레이블이 읽히는 모든 위치와 용도. 용도는 셋 중 하나로 분류한다: 학습 계산 / 모델 선택 / 지표.

### F. 무작위성 소비 지점

- 학습 경로에서 전역 `random`, numpy, torch RNG를 소비하는 모든 위치.
- 전용 생성기를 쓰는 위치와 오프셋.

### G. 임베딩 덤프와 측정 도구

- `emb_best.npy`:
  - 어느 텐서인가(어느 모듈의 출력, LayerNorm 전/후)
  - 어느 모드(train/eval)에서, 어느 에폭에 저장되는가
  - 저장 코드 위치
- 현재 플래그로 다음 덤프가 가능한지: 에폭별 덤프, 초기화 직후(첫 optimizer step 전) 덤프.
- 다음 지표 각각의 계산 코드 위치, 입력 형식, 사용 레이블, 다른 스크립트에서 함수로 import할 수 있는지:
  - kNN 순도(T14)
  - 그룹별 코사인 프로토타입 probe(T12)
  - 유효 차원·BW(T13)
