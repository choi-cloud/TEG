# (ii) Dual-View Rehearsed Trust — 종료 기록 (2026-10-06)

브랜치 `dual_view_trust` (분기 `t06b` → `t08` → `t08b`). 학습 코드 변경은 `--dump_logits` 플래그 하나뿐이다(읽기 전용).

## 1. 무엇을 시험했나
- 질문 1(J1): TEG 점수(관점 L)와 확산 특징 Â²X 코사인 점수(관점 D)를 섞으면 각각보다 나은가.
- 질문 2(J2): task(에피소드)마다 섞는 비율 α를 달리 고르면 고정 α보다 나은가. → (ii)에서 가짜 클래스(A)로 판단기를 학습할 이유가 있는가.
- 방법: 원본 TEG 18 run(3 데이터셋 × 1/5-shot × seed 3)의 valid·test 점수 덤프 → 오프라인 분석. 관점별 온도는 valid NLL로 보정. T08b에서 관점 L을 log 확률로 교정(T08은 확률을 logit처럼 쓴 정의 오류, 결론 동일).

- 에피소드별 α 선택의 추가 이득은 −1.2 ~ +0.1%p(J2 = 0/6).
- 확산 관점 단독이 TEG를 넘는 조건: 5/6(dblp 1-shot 제외).
- query 단위로 두 관점 중 하나라도 맞히는 비율은 84–96%로, 결합 결과보다 5–8%p 높다(남은 여지).
- 사전 등록 P46–P53: P49(α 방향)만 어긋남, 나머지 일치.

## 3. 결론
- **(ii)를 (A) + (C) 스토리로는 유지하지 않는다.** task 단위 신뢰 판단이 더할 것이 없으므로, 판단기와 이를 학습시킬 가짜 클래스(A)가 필요 없다. 온도를 맞춘 두 관점을 곱하면 query마다 더 확신하는 쪽이 이기는 효과가 이미 생긴다.
- **(C)는 남긴다**: "온도 보정 후 반반 결합(α = 0.5)". 학습 없이 TEG에 덧붙여 +1.9–6.8%p.

## 4. 다음으로 넘기는 것
- **기준선**: TEG + 확산 결합(α = 0.5, 온도 valid 보정). 이후 모든 방법이 넘어야 할 비교 대상.
- **코드**: `tools/fusion_baseline.py`(독립 함수 파일), `--dump_logits` 플래그.
- **랩미팅 자료 후보**: 결합 곡선(표 A, 가운데가 솟은 모양), query 단위 상보성(표 D).
- **(i)에 주는 근거**: 두 관점은 서로 다른 query를 맞힌다 → 확산 구조를 인코더에 보존하는 (i)의 전제에 근거. 단, (i)은 결합 기준선을 넘어야 의미가 있다.
